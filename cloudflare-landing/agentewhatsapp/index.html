O objetivo não é decorar uma stack. É entender as fronteiras entre as peças para conseguir trocar, depurar e evoluir cada uma delas.

01 / ARQUITETURA

uma mensagem atravessa um sistema inteiro.

Cada camada aparece separada para deixar claro o que recebe a mensagem, o que guarda estado, o que executa lógica e o que pode ser substituído depois.

01ENTRADAWhatsAppa mensagem chega pelo canal
02PONTEWebhooko evento é validado e encaminhado
03CONTEXTOSupabasehistórico e dados entram na consulta
04MODELOProvider de IAo contexto vira uma resposta
05SAÍDAWhatsAppa resposta volta para a conversa

02 / STACK

ferramentas entram como peças, não como promessa.

01WhatsApp / Uazapi

canal, instância e troca de mensagens

02Supabase

dados, histórico, autenticação e contexto

03Hostinger

backend, deploy e processo em execução

04Termius

acesso ao servidor e operação por SSH

05Provider de IA

modelo, contexto, custo e limites

03 / CAMINHO

primeiro funciona. depois fica sustentável.

01PROTOTIPAR

colocar o primeiro fluxo no ar.

Conectar o número, receber uma mensagem, buscar contexto, chamar o modelo e devolver uma resposta.

01conectar o canal
02estruturar os dados
03montar o fluxo
02OPERAR

entender o que mantém o sistema vivo.

Sair da demonstração e olhar para servidor, credenciais, logs, falhas e manutenção como parte do produto.

01publicar o backend
02separar segredos
03acompanhar a operação

04 / SAÍDA

sair sabendo continuar.

A aula não termina numa receita fixa. Ela termina quando você consegue explicar o fluxo e decidir o que trocar depois.

01entender a arquitetura antes de copiar código
02saber onde dados e contexto entram no fluxo
03separar canal, backend, banco e modelo
04continuar evoluindo sem depender de uma ferramenta única
